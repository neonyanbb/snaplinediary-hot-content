## 先核对：你的版本到底有没有这些项

Anthropic 迭代快，Focus Mode、Live Preview、Slack 集成等 **可能因账号、平台、版本而异**。开通前在应用内设置或 [Features overview](https://code.claude.com/docs/en/features-overview) 核对，避免文章写了你却找不到按钮。

## Focus Mode：减少上下文切换

适合：长会话重构、需要连续 45 分钟以上深度工作。  
做法：桌面端开启专注布局，屏蔽非必要面板（具体 UI 以客户端为准）。  
**实测感受**：对「专注时间」有帮助，但不替代 Plan Mode；该漏的文件仍会漏。

## Live Code Preview：前端反馈环

适合：组件库、静态页、可本地 dev server 的项目。  
局限：后端 API、批处理任务收益有限；预览依赖本地环境能跑起来。

## Model Picker：成本与质量平衡

策略示例：

- 读全库、写计划：强模型
- 改样板测试、格式化：较弱模型
- 失败两次：升级模型，而非无限重试

记录一周账单，看是否真省，避免「小模型反复失败更贵」。

## Slack / Discord 集成：异步把关

适合：团队希望 **在聊天里批准计划** 再继续。风险：频道权限与泄露；应用最小权限 Bot，敏感仓库用私有频道。

## 快速核对清单

- [ ] 客户端版本 ≥ 你需要的功能起始版
- [ ] Model Picker 在会话内可切换且计费符合预期
- [ ] Preview 能连上本地 dev URL
- [ ] 协作集成仅连接必要仓库

## 协作集成的最小权限

Slack/Discord Bot 只需：读指定频道、发 thread 回复、可选 react。不要给 Admin。仓库访问用 GitHub App 细粒度权限，而不是个人 PAT 全家桶。

## 预览功能的局限清单

Live Preview 依赖本地 dev server 与浏览器路径；SSR、WebSocket、鉴权 cookie 场景常失效。遇到「预览正常、生产异常」时，回到真实环境测，不要迷信预览截图。

## Focus 模式适用任务

适合：长会话重构、需要少打扰的深度改码。不适合：频繁切换微任务。开 Focus 前先写清「本会话只完成 X」，结束条件为测试绿或 PR 开完。

## 预览与协作（2026 常见用法）

本地预览用于前端改 UI；协作会话用于结对审查 Agent diff。规则：谁启动会话谁负责 merge，避免双人同时批准冲突 diff。

## 模型切换策略

| 任务 | 模型档 |
|------|--------|
| 注释/格式 | 小 |
| 跨模块重构 | 大 |
| 读日志排错 | 中 |

在会话开头声明模型档，避免中途切换导致上下文风格断裂。

## 预览环境与服务端口

前端预览要固定端口，避免 Agent 每次随机端口导致 E2E 失败。在 `CLAUDE.md` 或项目说明里写：`npm run dev` 端口 3000，预览 URL 模板。减少 Agent 猜测。

## 协作会话的权限

谁创建会话谁拥有终止权；访客只读。避免两人同时批准冲突的工具调用。会话录音或导出日志供安全审计（若公司要求）。

## Focus 与深度工作块

把 Focus 会话限制在 90 分钟 Pomodoro 内，结束必须留下测试命令输出截图或日志摘要。防止「开 Focus 一整天却无合并」的虚假忙碌。

## 实操附录：Focus 会话复盘

每次 Focus 结束填三行：本会话目标、实际改动文件数、测试命令输出是否粘贴。未粘贴测试输出视为未完成。经理周会只抽查表格，不抽查代码，降低微观管理成本。

## 读者可执行检查

开一次 Focus 会话并提交测试输出截图。无截图视为未完成 Focus 试点。

## 发布前核对

最近一次 Focus 必须附测试命令输出。三次无输出则 Focus 权限收回，改回普通会话。

## 会后跟进

Focus 截图文件夹设周清理，经理只抽查是否存在，不看内容细节。

## 版本记录

Focus 权限可按人授予，季度复审。滥用 Focus 长时间挂机会被收回，改回普通会话模式。
