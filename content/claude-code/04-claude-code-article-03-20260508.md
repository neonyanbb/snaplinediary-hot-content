## 实验设定（可复现）

时间跨度约半年，项目类型：Python/TypeScript 混合单体 + 若干开源贡献。每月固定一项 **标准任务**：给遗留模块加测试并修 lint，记录：完成时间、返工次数、是否跑过测试。工具轮换包括：纯补全型、IDE Agent 型、终端 Agent 型。结论因人而异，下面是 **我的** 排序逻辑。

## 第一轮淘汰：纯补全

补全在「已知下一行写什么」时极快，但在「不知道该动哪些文件」时几乎无用。标准任务里，补全型需要我手动找文件、复制错误信息，整体时间没降多少。淘汰理由：**不解决协调问题**。

## 第二轮淘汰：只会改当前文件的 IDE Agent

部分 Agent 模式擅长单目录，但遇到 `packages/` 多包仓库时，计划常漏测试包或 CI 配置。返工集中在「第二次才改对路径」。保留 IDE 工具用于 **边写边看 diff**，不再让它独扛大重构。

## 留下 Claude Code 的三点

1. **终端里自然跑测试**：失败日志直接进会话，迭代链短。
2. **Plan Mode 可审**：大改前有文件清单（配合人工看 diff）。
3. **MCP + Hooks 上限高**：能接 issue 系统与公司门禁（需自己配）。

同时 **仍每天用 Cursor** 做：UI 微调、快速浏览陌生文件、Tab 补全。这不是失败，而是 **按任务分型**。

## 决策框架（给你抄）

| 任务特征 | 优先 |
|----------|------|
| 单行/单文件、你在看 | Cursor / IDE |
| 3+ 文件、要跑测试 | Claude Code + Plan |
| 只要问答、不改库 | 普通 Chat |
| 要 IM 记长期背景 | Hermes 等网关 |

## 六款试用的记录字段（可复制）

建议表格列：工具名、安装耗时、标准任务分钟数、返工次数、是否跑测试、是否愿付月费、一年后是否仍安装。半年后回头看，最常留下的不是评分最高的，而是 **最省协调时间** 的。

## 何时回退到纯 IDE

若连续两周 Agent 改库引入的 bug 多于自己写的，说明流程有问题：可能测试太薄、可能计划太宽、可能模型太激进。回退到 Cursor 手写 + 偶尔 Agent 并非失败，而是校准节奏。

## 我留 Claude Code 的三条硬理由（可替换为你的）

1. 终端里 Plan+shell 闭环，远程 SSH 友好。  
2. Hooks 能封路径，团队敢放权。  
3. 与 Anthropic 模型迭代同步，长上下文改库稳定。  

你的理由必须来自实测表，不要复制本文。

## 迁移残留风险

从 Cursor 迁出时检查：未提交的 Agent 分支、`.cursor` 规则是否已翻译成 Claude 项目说明、MCP Server 端口是否冲突。花半天做清理，比带着双工具再跑一个月便宜。

## 知识转移

主工具定后，把 `.claude` 规则、Hooks 样例、Plan 模板放进团队仓库，离职交接才有抓手。

## 离职交接

交接包含：主工具、Hooks 路径、MCP 清单、标准任务表、上月 ROI。接班人用同一任务跑一遍，差异超过百分之三十则复盘流程而非怪工具。
