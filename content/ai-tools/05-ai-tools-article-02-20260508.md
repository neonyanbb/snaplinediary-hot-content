## 测评方法与维度

维度各 1～5 分，主观但可复现：

1. 任务完成度：标准任务能否一次过，不编造 API、不引入无关改动
2. 集成成本：从安装到产出第一行有效代码/文本的分钟数
3. 记忆/上下文：跨天是否记得项目约束，长文后段是否违背前段规则
4. 月费透明度：是否容易超支，账单是否可预测

标准任务示例：修一个 failing unit test（要求只改测试允许的文件，不改依赖版本）；把 800 字杂乱笔记转化为带负责人和截止日期的决策表；用自动化工具把 Slack 消息写进 Google Sheet 一行，失败时返回明确错误而非静默成功。

## 编程场景

| 工具 | 月费 | 任务完成度 | 集成成本 | 记忆 | 月费透明度 | 适合 | 弱项 |
|------|------|------------|----------|------|------------|------|------|
| Claude Code | API 按量 | 4.5 | 3 | 4 | 2 | 重构、跨目录迁移 | 要习惯 CLI，大 refactor 账单可能 $30+ |
| Cursor Pro | $20 | 4 | 5 | 3 | 3 | 全栈日常开发 | 重度 Agent 耗额度，大项目易触发上限 |
| GitHub Copilot | $19 | 3.5 | 5 | 3 | 5 | 已有 GitHub 生态的团队 | Agent 深度依版本，多文件支持仍弱于 Cursor |
| Cline | 扩展免费 | 4 | 3 | 3 | 4 | 要审计、需自管 API Key | 自管 API，新手配置 MCP 门槛高 |
| Windsurf | $15～20 | 4 | 3 | 4 | 4 | 追求 IDE 内闭环 | 独立 IDE，迁移成本 |
| Aider | 开源免费 | 3.5 | 2 | 3 | 5 | 终端党、脚本化批量处理 | 无 GUI，diff 阅读在终端 |

Claude Code 的实测表现：在 Python 项目里让它修 3 个 failing test，输入 `claude`，然后描述错误。它在 70% 的情况下能定位到正确文件，但约有 15% 的概率会顺手升级某个依赖版本或修改无关配置。对策是显式约束：「只改 `tests/` 目录下的文件，不要碰 `pyproject.toml`」。加上约束后一次通过率提升到 85%。

Cursor 的 diff 体验是六款中最好的，inline diff 支持逐块接受/拒绝。但 2026 年 5 月的版本中，Agent 模式对 monorepo 的大目录索引仍有卡顿，10 万行以上的仓库首次索引可能耗时 3～5 分钟。

Copilot 的强项是生态集成：在 VS Code、JetBrains、Neovim 里无缝可用，Tab 补全延迟低于 100ms。但 Copilot Agent（多文件模式）直到 2026 年 4 月才进入 Public Preview，且需要 Copilot Business 以上档位。个人 Pro 用户仍主要以补全为主。

反例：同时开 Cursor Agent 与 Claude Code 改同一分支。两者都读 `.git`、都写文件，冲突率超过 40%。某团队曾因此丢失半天工作，最后规则定为「同一分支同一时间只开一个 Agent」。

## 写作场景

| 工具 | 月费 | 长文结构 | 约束遵循 | 多模态 | 记忆 | 弱项 |
|------|------|----------|----------|--------|------|------|
| Claude 3.7 Sonnet | $20 Pro | 5 | 4 | 2 | 4 | 贵，免费档额度紧张 |
| ChatGPT GPT-4o | $20 Plus | 4 | 3 | 5 | 3 | 记忆参差，长文一致性不如 Claude |
| Notion AI | $10 | 3 | 3 | 1 | 3 | 绑 Notion，离开平台无价值 |
| Gemini 2.5 Pro | $20 Advanced | 3.5 | 3 | 4 | 3 | 代码口碑弱于 Claude，写作中规中矩 |

Claude 在 8000 字以上的长文里表现最好。实测：让它写一份 1.5 万字的技术规范，前 5000 字设定「所有 API 必须 RESTful、禁止 GraphQL」，后 10000 字里 Claude 只出现 2 次违规。ChatGPT 在同样测试中违规 7 次，需要人工二次校对。

约束遵循测试：给工具输入「输出一份产品对比表，不得出现竞品公司真实名称，用 A 公司/B 公司代替」。Claude 100% 遵循，ChatGPT 约有 10% 的概率在脚注里泄露真实名称，Gemini 约有 15% 的概率在总结段里违规。

Notion AI 的真正价值不是生成质量，而是「在已有文档库里生成」。你让它在 50 篇笔记里找「所有与 Q3 目标相关的待办」，这是通用 Chat 做不到的。但如果你的写作流程是「在 Notion 外写草稿，再粘贴进去」，Notion AI 的价值大打折扣。

## 生产力场景

Slack AI、Notion AI、Zapier Central 的价值在嵌入已有流，不是单独打开网页。测评标准是：是否减少复制粘贴次数。

Zapier Central 在 2026 年 5 月的定价是 $20/月起步，支持自然语言描述自动化。实测：「当 Slack #support 频道有新消息时，把它写入 Google Sheet 的 A 列，并标上时间戳」。配置耗时约 8 分钟，但复杂条件（如「只处理包含『urgent』的消息」）需要切换到传统编辑器，自然语言对边界情况识别率约 60%。

Make 的免费档支持 1000 次操作/月，对 5 人以下团队够用。它的优势是可视化流程图和错误日志清晰，失败时能看到具体哪一步、返回什么 HTTP 状态码。Zapier 的失败日志更简略，排查多花 20% 时间。

Slack AI 的会议摘要功能：对英语会议准确率约 85%，对中文混合英文的技术会议准确率降到 65% 左右，常把「redis cluster」识别为「Redis 公司」或「红色集群」。目前不适合作为严肃决策的唯一记录源。

## 垂直黑马

Devin 类云 Agent（如 Cognition Devin、Factory Code Droid）月费 $200～500，适合 issue 堆积严重的团队。实测：给一个带验收标准的 ticket（「给 `/health` 端点加数据库连通性检查，返回 503 时包含具体失败原因」），Devin 能在 20～40 分钟内提交 PR。但无验收标准的模糊 ticket（「优化性能」）产出极不稳定，可能改无关代码或提交不可合并的 diff。

本地开源 Agent（OpenHands、SWE-agent）隐私好，但运维成本高。OpenHands 需要 Docker 运行，最小配置 8GB RAM + 4 核 CPU，GPU 非必须但推荐。一次标准 issue 处理约消耗 $2～5 的 API 费用（若接 Claude API），加上服务器电费摊销。适合有平台工程师的团队，不适合「装完就不管」的场景。

退出成本检查：Devin 的对话历史和配置可导出为 JSON，但云沙箱里的临时文件在任务结束后 24 小时清除。OpenHands 的对话存在本地 SQLite，可备份。选型前必须确认：能否在 48 小时内停用并删除所有数据？若答案含糊，不要把生产 issue 队列押上去。

## 测评如何落地到精简

把上述评分表按月填写，只保留总分最高且有主任务的两行，其余退订。编程类与写作类分开评，避免用写作用户体验去选 IDE Agent。

场景化验收比逛官网 demo 更有效：

编程：指定 failing test 文件路径，要求 Agent 只改测试允许的文件，记录是否改了计划外文件、CI 是否通过。

写作：给 800 字杂乱笔记，要求输出决策表三列（事项/负责人/截止日期），检查是否编造负责人或日期。

自动化：故意触发两次同样的 Slack 消息，检查 Sheet 是否重复行（幂等性）。

若某工具无法在 90 分钟内完成对应任务，评分上限封顶 3 分，避免「看起来很强但落不了地」。

## 局限与不适合谁

评分含主观性，你的语言栈会改变排序。Rust 开发者可能觉得 Claude Code 比 Cursor 更好，因为 Claude 对类型系统的理解更深；React 开发者可能更依赖 Cursor 的组件级索引。移动端开发者（Swift/Kotlin）选择更少，Copilot 的补全质量目前仍领先。

企业协议可能锁定 Copilot，无法自由选。若公司已与微软签 E5，Copilot 往往捆绑折扣，此时切换成本不只在月费，还在合规与审计流程。本文不收录国内特有产品全表，有出海合规需求的团队需额外评估。请用你自己的标准任务重打分，不要照搬本表排序。
