## 测评方法

维度（各 1～5 分，主观但可复现）：

1. **任务完成度**：标准任务能否一次过  
2. **集成成本**：多少分钟接入现有栈  
3. **记忆/上下文**：跨天是否记得项目  
4. **月费透明度**：是否易超支  

标准任务示例：修一个 failing unit test；把 800 字笔记变三点摘要；用 Zapier 连 Slack→Sheet 一条自动化。

## 编程场景

| 工具 | 强项 | 弱项 | 适合 |
|------|------|------|------|
| Claude Code | 多文件+shell | 要习惯 CLI | 重构、迁移 |
| Cursor | diff 体验 | 重度 Agent 耗额度 | 全栈日常 |
| Copilot | 生态、企业 | Agent 深度依版本 | 已用 GitHub |
| Cline | 开源、MCP | 自管 API | 要审计 |

**反例**：同时开 Cursor Agent 与 Claude Code 改同一分支，易冲突。

## 写作场景

| 工具 | 强项 | 弱项 |
|------|------|------|
| Claude | 长文结构 | 贵 |
| ChatGPT | 多模态插件 | 记忆参差 |
| Notion AI | 库内写作 | 绑 Notion |

## 生产力场景

Slack AI、Notion AI、Zapier Central：价值在 **嵌入已有流**，不是单独打开网页。测评看：是否减少复制粘贴次数。

## 垂直黑马（2026 常提）

- **Devin 类云 Agent**：适合 issue 堆积，贵且要审 PR  
- **本地开源 Agent**（OpenHands 等）：隐私，运维成本高  

详见 GitHub 项目栏 OpenHands、Nanobot 文。

## 三步删订阅

1. 列出上月打开超过 5 次的工具  
2. 每个工具对应 **一个** 主任务，无任务则退订  
3. 保留「通用 + 编码 Agent」两层各一

## 延长测评：写作与自动化

写作场景除「润色」外，应测 **结构化输出**（表格、JSON、大纲层级）与 **长文一致性**（后段是否违背前段约束）。自动化场景测 Zapier/Make：失败时是否可读错误、是否支持重试。黑马工具重点看 **退出成本**：数据能否导出。

## 场景化验收命令

编程：指定 failing test 文件路径，要求 Agent 只改测试允许的文件。写作：给 800 字杂乱笔记，输出决策表三列（事项/负责人/截止）。自动化：Slack 消息触发写 Sheet 一行，失败须返回 API 错误而非静默成功。三类任务各做一次，比逛官网 demo 更能筛掉营销稿。

## 黑马工具的退出检查

Devin 类、OpenHands 类上线前问：能否导出对话与配置？能否在 48 小时内停用并删云沙箱？若答案含糊，不要把生产 issue 队列押上去。本地 Agent 还要问：谁负责夜间 GPU 账单与镜像漏洞补丁。

## 写作场景深度测评项

除润色外，测 **约束遵循**：要求「不得出现竞品名」看是否违规；测 **结构稳定**：同样输入三次，大纲层级是否一致；测 **引用诚实**：要求附来源，看是否编造 URL。编程场景则测 **测试是否真绿**：本地与 CI 各跑一遍。自动化场景测 **幂等**：同一条 Slack 触发两次，Sheet 是否重复行。

## 评分如何落地到采购

把四人评分表（完成度/集成/记忆/月费）的加权分写进内部 wiki，设阈值：低于 3.5 且两周未用的工具自动进入退订候选。避免「评分表做了但没人看」的形式主义。

## 十二款之外的替补规则

若主工具两个月评分下降，只允许从 **同类** 替补池替换一个，例如 Cursor 换 Windsurf，而不是再加第三个 IDE Agent。替补试用仍用同一标准任务表，两周后定去留。

## 实操附录：十二款工具的「一条标准任务」

编程：fork 官方示例仓，修一个 failing test，要求 CI 配置与你们主栈相同语言。写作：把真实会议纪要（脱敏）变决策表，检查是否编造负责人。生产力：用现有 Slack 工作区触发一次写表，记录 OAuth 审批耗时。垂直黑马：只开文档 PR，禁止改依赖锁文件。每款工具若无法在 90 分钟内完成对应任务，评分上限封顶 3 分，避免「看起来很强但落不了地」。

## 读者可执行检查

请为你最常用的编程工具填完评分表四列，并把「反例」场景用一句话写给同事。若写不出反例，说明你可能不需要第二款编码 Agent。

## 发布前核对

十二款里至少填完四款的真实评分。编程类若最高分仍低于 3 分，说明标准任务选得太难，应换 smaller ticket 而不是换第十二个工具。

## 会后跟进

把测评表最高分工具设为默认，次高分工具降级为「仅当主工具挂掉时试用」，写入 onboarding。

## 局限与不适合谁

评分含主观性，你的语言栈（Rust/移动端）排序会变。企业协议可能锁定 Copilot，无法自由选。本文不收录国内特有产品全表。请用你自己的标准任务重打分。
