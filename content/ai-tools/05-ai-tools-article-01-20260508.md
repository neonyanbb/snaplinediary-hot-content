## 效率焦虑的真正来源

问题常不是工具少，而是 **同一类能力买了两份**：Cursor Agent 与 Claude Code 都在改仓库，Notion AI 与 ChatGPT 都在写摘要。2026 年市场已默认「Agent 能多文件改、能跑命令、能交 PR」，区别只在载体与治理（见 [Tembo Agentic 对比](https://www.tembo.io/blog/agentic-ai-coding-tools)）。

## 三层栈（建议只各选一项）

| 层 | 作用 | 代表 |
|----|------|------|
| 通用推理 | 写作、分析、脑暴 | ChatGPT、Claude、Gemini |
| 编码 Agent | 改库、跑测试 | Cursor、Claude Code、Copilot Agent |
| 工作流/记忆 | 自动化、长期上下文 | Zapier、Hermes 网关等 |

新入坑：**先填满编码 Agent 一层**，再考虑第三层；不要先买五个通用订阅。

## 与「三足鼎立」通用模型的关系

ChatGPT 生态广、Gemini 绑 Google、Claude 长文与代码口碑好，这是 **通用层** 竞争，不替代 IDE Agent。实践组合：

- 长文/规范写 Claude 或 ChatGPT  
- 日常改代码 Cursor 或 Claude Code  
- 团队文档在 Notion/Slack AI  

## 两个最小组合

**独立开发者（月费敏感）**  
Copilot 或 Cursor 其一 + 按需 Claude API，通用 Chat 用免费档。

**小团队（要审计）**  
Copilot Business + 规定大改必须 Plan/PR，禁止个人乱接 MCP 写库。

更细 ROI 见本站《CLI Agent 与 Background Agent 月费》。

## 反模式：订阅堆叠

同时订阅 ChatGPT Plus、Claude Pro、Cursor Pro、Copilot、Notion AI，而每周深度使用不超过两个，属于典型堆叠。每月花 15 分钟审账单，原则：**没有标准任务支撑的就退订**。

## 内部推广话术（给技术负责人）

不要说「买 AI 省人」，要说「用标准任务测省下的协调小时，是否大于月费」。把测时表格贴进 OKR 附录，比口号容易获批。

## 标准任务测时表（建议复制）

| 任务 | 手工(分) | Agent(分) | 返工(分) | 通过 |
|------|----------|-----------|----------|------|
| 在现有仓加健康检查端点 | | | | |
| 修 3 个 failing unit test | | | | |
| 把会议纪要变决策+待办 | | | | |

规则：每周只在一个工具上跑同一行，避免把学习曲线当成工具差距。Agent 结束后记录是否改了计划外文件、CI 是否绿。连续两周返工高于手工，暂停该层续订，而不是再加第四个订阅。

## 企业采购可贴的 RFP 片段

```text
供应商须说明：客户代码是否用于训练、是否支持 VPC/自托管、审计日志保留天数、每 seat API 上限。
验收：两周内完成上表三项任务，节省人时须大于许可费加内部运维摊销。
禁止：未经评审默认开启写库类 MCP。
```

## 三层栈迁移顺序（90 天）

第 1～30 天：只保留一个编码 Agent，统一分支策略与测试命令。第 31～60 天：若 IM 里决策多，再加 Hermes 或同类网关做捕获，不替代 IDE。第 61～90 天：评估 Zapier 类自动化是否真减少复制粘贴。任何阶段出现「两个 Agent 改同一分支」，先砍一个，再谈扩容。

## 独立开发者四周实验课表

| 周 | 编码 Agent | 通用 Chat | 记录 |
|----|------------|-----------|------|
| 1 | 只读扫树 | 写文档大纲 | 耗时 |
| 2 | 修单测 | 润色 README | 返工 |
| 3 | 小重构 | 会议纪要 | 是否超支 |
| 4 | 复盘退订 | 复盘退订 | ROI |

每周只允许动一层订阅，否则无法归因。第四周若编码层 ROI 为正、通用层为负，退订通用 Plus 而非再加 Zapier。

## 与热站其他栏目的阅读顺序

若你已确定编码 Agent，下一步读 Claude Code 栏的 Plan 与 Hooks；若关心开源 Agent 平台，读 GitHub 项目的 OpenHands；若需要 IM 记忆，读 Hermes 上手指南。按任务跳转，不要线性读完所有栏。

## 实操附录：三分法落地工作坊（90 分钟）

0～15 分：参会者各自写下本周三个真实任务（改码、写作、自动化）。15～35 分：把任务贴到三层栈白板，只允许每任务占一层。35～55 分：对落在同一层的重复工具画叉，确定退订候选。55～75 分：填写标准任务测时表空白行，约定下周同一时间复测。75～90 分：指定一名「订阅守门人」，负责季度复核，避免又堆新工具。工作坊输出应拍照存档，而不是散落在聊天记录里。

## 读者可执行检查

离开本文前，请确认你已在纸上写出三层栈各一个工具名、一个待退订候选、以及下周要复测的标准任务。三者缺一，三分法仍停留在概念层。

## 发布前核对

确认你已写出三层栈各一层的一个工具名，并圈出下季度要退订的订阅。若编码层与通用层仍是同一类能力（两个都在改摘要），先退订一个再谈扩栈。

## 会后跟进

工作坊结束后 48 小时内，守门人把退订清单发给财务，避免自动续费再扣一月。

## 局限与不适合谁

三分法随并购变化，名称可能合并。若你非知识工作者（极少写码、不写文档），通用 Chat 足够。本文不推荐具体股票或限时优惠。采购前用 30 天试点 + 标准任务计时，比读榜单纯。
