## 500 元教训：买了「最好」却用回免费档

常见路径：看榜单买最贵组合 → 两周后仍只打开网页 Chat → 订阅自动续费。根因是把 **排行榜第一名** 当成 **你的任务最优**，忽略集成与记忆。

## 三权重模型

| 维度 | 权重 | 问什么 |
|------|------|--------|
| 任务匹配 | 40% | 主任务是写码、写作还是自动化？ |
| 集成成本 | 30% | 能否 30 分钟接入 Git/Slack？ |
| 记忆能力 | 30% | 下周能否接着上周项目？ |

打分 1～5，加权后选最高，而非选名气。

## 失败模式

1. **功能溢出**：买 Agent 却只用来改错别字  
2. **孤岛**：五个工具互不传上下文  
3. **无验收**：从不定义「怎样算用好」

## 场景表

**独立开发者**  
主任务：编码 + 偶尔文档 → Copilot 或 Cursor 一项 + Claude API 按需。

**创作者**  
主任务：脚本/长文 → ChatGPT 或 Claude + Notion 归档，Hermes 可选做 IM 捕获。

**企业团队**  
主任务：合规协作 → Copilot Business，试点 Claude Code 需安全评审。

## 30 天试点清单

- [ ] 第 1 天：定一个标准任务与通过标准  
- [ ] 第 7 天：记录完成时间与返工  
- [ ] 第 14 天：删未打开超过 2 次的订阅  
- [ ] 第 30 天：只保留加权分最高组合

## 加权分实战演算

假设：任务匹配 5、集成 3、记忆 4。加权 = 5*0.4+3*0.3+4*0.3 = 4.1。另一工具 4,5,2 → 3.7。数字让讨论从「我喜欢」变成「我们看重集成」。

## 供应商锁定信号

导出困难、专有格式、只能在其云编辑，都是锁定信号。选型时问：能否导出 markdown/标准 API？退出成本多大？

## 任务→工具决策树（文字版）

1. 是否改仓库？否 → 通用 Chat；是 → 下一步。  
2. 是否跨 10+ 文件？否 → Tab 补全可能够；是 → 编码 Agent。  
3. 是否跨天 IM 决策？是 → 加网关记忆；否 → 可不加。  
4. 是否接内部 API？是 → 查 MCP 只读支持；否 → 跳过。  

走完四步仍有两个候选，用同一标准任务测 90 分钟，不要投票选品牌。

## 反模式对照表

| 反模式 | 修正 |
|--------|------|
| 为写邮件买 Copilot Business | 用通用 Chat |
| 为改 CSS 开 Claude Code | 用 IDE 补全 |
| 为记待办装三个 Bot | 单通道 Hermes |
| 无测试就让 Agent push | 先 Hooks 再写库 |

## 采购会议三句话

「我们按任务选工具，不按榜单。」「验收用标准任务表，不用 demo。」「季度复核订阅，无任务即退。」

## 任务类型词典（团队共用）

| 任务标签 | 允许工具 |
|----------|----------|
| TYPO | Tab 补全 |
| BUGFIX-1F | 单文件 Agent |
| REFACTOR-M | Plan+Agent |
| ARCH-WRITE | 通用 Chat |
| IM-CAPTURE | 网关 |

新需求先贴标签再选工具，减少会议争论。标签由 Tech Lead 维护，一季复审一次。

## 选型失败的组织信号

同时存在三个以上编码 Agent 订阅；PR 里经常出现「Agent 改坏但无人认领」；月费超支却无人能说出主任务。出现两条即应冻结新采购，先做退订与流程修复。

## 新成员第一周作业

认领一个任务标签，用指定工具完成并记录耗时。导师只检查表格，不争论品牌。第一周禁止同时开两个编码 Agent 订阅，避免习惯混乱。

## 实操附录：任务标签试点两周

在 Jira 或 Linear 增加必填字段「任务标签」，只允许 TYPO、BUGFIX-1F、REFACTOR-M、ARCH-WRITE、IM-CAPTURE 五类。Tech Lead 每周抽 10 张票，看标签与真实改动是否一致。不一致的票退回重标。两周后统计：哪类票误用了昂贵 Agent，针对性培训而非全员加课。

## 会后跟进

任务标签字段设为必填，漏填工单由 bot 自动退回，减少「临时用错工具」的借口。

## 局限与不适合谁

模型不适合极度创新、零先例的研发（仍要人主导）。三权重是你自定义的，金融合规可能强制 100% 集成成本权重。本文不提供法律咨询。试点仍可能因促销误续费，请设日历提醒取消。
