## 500 元教训：买了「最好」却用回免费档

常见路径：看榜单买最贵组合，两周后仍只打开网页 Chat，订阅自动续费。根因是把排行榜第一名当成你的任务最优，忽略集成与记忆。

一个真实案例：某全栈开发者看了「2026 最强 AI 编程工具」榜单后，同时订阅 Cursor Pro ($20)、Claude Pro ($20)、GitHub Copilot ($19)，月费 $59。两周后发现：日常 React 开发用 Cursor 足够，Claude Pro 只在写文档时打开，Copilot 的 Tab 补全与 Cursor 重叠。第三周起，Claude Pro 再也没打开过，但自动续费继续扣款。三个月后他才想起来退订，浪费了 $60。

更隐蔽的代价是注意力：每个工具都有自己的快捷键、上下文规则和额度限制。在三者之间切换，重建上下文的成本约为 5～10 分钟/次。若一天切换 4 次，等于损失半小时有效工作时间。

## 三权重模型与实战演算

| 维度 | 权重 | 问什么 | 低分信号 |
|------|------|--------|----------|
| 任务匹配 | 40% | 主任务是写码、写作还是自动化？ | 买 Agent 却只改错别字 |
| 集成成本 | 30% | 能否 30 分钟内接入 Git/Slack/现有栈？ | 装完三天还没产出第一行代码 |
| 记忆能力 | 30% | 下周能否接着上周项目？ | 每次都要重新解释项目结构 |

打分 1～5，加权后选最高，而非选名气。

实战演算：假设你在评估 Cursor 和 Claude Code。

Cursor：任务匹配 5（IDE 内全栈开发）、集成 5（安装即用）、记忆 3（代码图索引好，但跨设备同步偶有延迟）。加权 = 5*0.4 + 5*0.3 + 3*0.3 = 4.4。

Claude Code：任务匹配 4.5（终端重构极强，但日常开发不如 IDE 顺手）、集成 3（要配 API Key）、记忆 4（项目级上下文保持好）。加权 = 4.5*0.4 + 3*0.3 + 4*0.3 = 3.9。

若你的主任务是日常全栈开发，Cursor 胜出。若主任务是大型迁移或脚本化批量处理，Claude Code 的任务匹配可能提到 5，结果反转。

权重可自定义。金融合规团队可能把集成成本权重提到 50%（因为要过安全评审），独立开发者可能把任务匹配提到 50%（因为效率第一）。关键是把讨论从「我喜欢」变成「我们看重什么」。

## 失败模式与修正

功能溢出：买 Cursor Pro 却只用来改 CSS 颜色或拼写错误。修正：用 IDE 自带补全或免费 Tab 补全即可，不要让 $20/月的 Agent 做 $0 的活。

孤岛：五个工具互不传上下文。例如用 ChatGPT 写需求文档，用 Cursor 写代码，用 Notion 记笔记，三者之间没有共享上下文。修正：至少保证编码 Agent 能读文档链接，或通用 Chat 能输出可直接粘贴到代码库的格式。

无验收：买了工具却从不定义「怎样算用好」。修正：选定一个标准任务（如「给无测试模块补测试并修 lint」），记录手工耗时与 Agent 耗时，连续两周对比。

## 场景表与最小组合

独立开发者：主任务是编码加偶尔文档。推荐 Copilot 或 Cursor 一项加 Claude API 按需。月费控制在 $20～35。接入顺序：第一天装 Cursor，跑通一个标准任务；第七天评估是否还需要第二个工具；第十四天退订未打开超过 2 次的订阅。

创作者：主任务是脚本、长文、视频大纲。推荐 ChatGPT 或 Claude Pro 一项加 Notion 归档。Claude 适合长文结构，ChatGPT 适合多模态（图像分析、语音输入）。若已有 YouTube 或播客工作流，可加 Descript 或类似工具的 AI 功能，但不要超过两层。

企业团队：主任务是合规协作。推荐 Copilot Business（已有 GitHub 生态）或 Cursor Team（要审计日志）。试点 Claude Code 需安全评审，因为它需要 API Key 管理，且操作日志不如 Copilot 集成在 GitHub 组织面板里直观。

## 30 天验证清单

第 1 天：定一个标准任务与通过标准。例如「在现有 Express 路由上加输入校验，并确保相关测试通过」。通过标准：CI 绿、代码评审无重大问题、耗时不超过手工的 80%。

第 7 天：记录完成时间与返工次数。若 Agent 改了计划外文件或引入 lint 错误，算一次返工。

第 14 天：删未打开超过 2 次的订阅。不要等月底，现在就退订。

第 30 天：只保留加权分最高组合。若两款工具加权分接近（差距小于 0.3），选审计日志更完整的那款，企业环境可追溯性常比快 5% 更重要。

## 任务到工具的决策树

1. 是否改仓库？否，转向通用 Chat（Claude/ChatGPT/Gemini）。是，下一步。
2. 是否跨 10 个以上文件？否，Tab 补全可能够（Copilot 或免费档）。是，需要编码 Agent。
3. 是否跨天 IM 决策？是，加网关记忆（Hermes 或同类）。否，可不加。
4. 是否接内部 API？是，查 MCP 只读支持（Cline 或自建 MCP）。否，跳过。

走完四步仍有两个候选，用同一标准任务测 90 分钟，不要投票选品牌。90 分钟测试应包括：只读列目录、改 1 文件加单测、接只读 MCP（如有需要）。记录每步的分钟数和 diff 清晰度。

## 供应商锁定与退出检查

导出困难、专有格式、只能在其云编辑，都是锁定信号。选型时问三个问题：

能否导出 markdown 或标准 API？Cursor 的规则文件是 proprietary 的，难以导出；Claude Code 的聊天记录可导出为文本；Notion 支持批量导出为 markdown 和 HTML。

退出成本多大？Copilot 退出不影响已有代码，但失去补全；Zapier 退出需要重建自动化流程；Devin 类云 Agent 退出意味着失去所有云沙箱配置。

数据能否在 48 小时内完全删除？云端工具查 GDPR/CCPA 删除流程；本地工具确认缓存目录位置（如 Cursor 的 `~/.cursor`、Claude Code 的 `~/.claude`）。

## 局限与不适合谁

三权重模型不适合极度创新、零先例的研发。若你在探索全新架构（无前例代码可参考）或进行前沿算法研究，Agent 的「基于模式补全」优势无法发挥，仍要人主导。此时工具选型不重要，重要的是算力和实验环境。

金融合规可能强制 100% 集成成本权重，导致某些高任务匹配但难审计的工具被排除。本文不提供法律咨询，GDPR、SOX、等保等要求需法务确认。

模型评分是主观的，不同语言栈结果不同。Rust 开发者给 Claude Code 的任务匹配分可能高于 Cursor，因为 Claude 对类型系统的理解更深；Vue 开发者可能更依赖 Cursor 的组件级索引。不要照搬他人评分，要用自己的标准任务实测。

试点仍可能因促销误续费。建议订阅当天就在日历里设提醒，在免费试用到期前 3 天决定是否续订。很多工具的「首月半价」会自动转为全价续费，若不主动取消，第二个月起按原价扣款。
