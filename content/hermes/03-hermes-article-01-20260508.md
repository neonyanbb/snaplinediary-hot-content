## 问题定义：缺的不是智商，是连续性

很多人和 AI 讨论技术方案后，第二天新开对话，背景全部丢失；手机、Slack、命令行各聊各的，等于三个陌生人。Hermes 的核心命题是 **跨会话、跨渠道记住你是谁**，而不是单次回答更花哨。官方 slogan「The agent that grows with you」指向的是：偏好、项目、决策在网关层累积，模型可以换，人设与任务上下文尽量保留。

这与 Claude Code 等 **代码库内 Agent** 互补：后者擅长改仓库、跑测试；Hermes 擅长在你已经分布在工作流里的 IM 和 CLI 上维持一条长期时间线。

## 架构三件套

**1. 单一网关进程**  
Telegram、Slack、Discord、WhatsApp、Signal、CLI 等入口共用一个 gateway（具体渠道列表以当前版本文档为准）。好处是运维边界清晰：挂一次进程、备份一份记忆库；坏处是网关成为单点，需要监控与自动重启。

**2. 记忆与模型解耦**  
对话与检索默认落在网关侧存储（SQLite + FTS5）；可选 Honcho 做更深用户建模。换底层 LLM 不应清空「上周在做什么项目」，这是与「把历史塞进超长上下文」不同的工程路径。

**3. 开放扩展**  
MCP 接外部工具，Skills（agentskills.io）接可复用能力包，社区仓库 [NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent) 持续发版（如 v2026.5.16 的 Grok OAuth、本地 OpenAI 兼容代理等）。适合愿意自己维护配置文件的团队，不适合只想点网页就用的用户。

## 三个可验证的使用场景

**跨天续写**：周一在 Slack 定下方案 A/B/C，周五在 CLI 问「最后选了哪个」，应能引用决策过程而非让你重讲一遍。

**跨设备记录**：通勤时用 Telegram 语音记待办，到办公室在另一通道追问「今早那条待办」，应能接上。

**多项目切换**：用标签或明确项目名区分上下文，避免把 A 项目的 API 密钥习惯带到 B 项目（仍需人工敏感信息纪律）。

每个场景都可以用「24 小时后再问同一事实」做通过/不通过测试，比看 demo 视频可靠。

## 是否值得投入：四条自检

| 自检项 | 若多为「是」 | 若多为「否」 |
|--------|--------------|--------------|
| 需要跨天、跨渠道同一助手 | 值得试 Hermes | 网页 Chat 即可 |
| 愿意维护网关进程与 Token | 可以自建 | 选全托管 SaaS |
| 需要接 IM 而非只在 IDE | Hermes 更合适 | 优先 Claude Code/Cursor |
| 接受开源、自己读 Release | 适合 | 选闭源省心产品 |

四条里至少命中两条，再花一个下午装网关；否则容易沦为「又一个聊天窗口」。

## 版本节奏与信息源

跟踪 Hermes 不要靠二手博客。建议固定三个信息源：GitHub Releases（功能与破坏性变更）、官方文档（配置字段）、你自己的网关日志（真实失败原因）。v2026.5 线增加了更多模型提供方与搜索类工具，但 **记忆与 MCP 的配置方式** 并不随模型切换而自动迁移，升级前先在测试 Bot 上复制一份数据目录。

若你使用 Docker 或 Modal/Daytona 一类无服务器后端，还要单独评估：进程休眠后记忆是否持久化卷上、Webhook 回调 URL 是否变化。很多人以为「上了云就不用管网关」，实际上 **网关仍是状态中心**，只是主机换了位置。

## 一周试运行里程碑

| 天 | 目标 | 通过标准 |
|----|------|----------|
| D1 | 网关 + 单通道 | 能收发消息 |
| D2 | 背景卡 + 探针 | 24h 后记得项目名 |
| D4 | 一个 Skill | 单任务成功 |
| D7 | 复盘 | 能导出三条 [KB] 结论 |

试运行结束仍达不到 D4，不要加 Honcho 和 MCP，先把基础链路做稳。

## 成本粗算：自托管并不免费

网关进程可以跑在旧笔记本或最便宜 VPS 上，但 **模型 API** 往往才是大头。若每天长对话 + 多通道，要单独设月度 API 上限。Honcho 等云服务再加一项。与「只买 Claude Pro 网页版」对比时，把运维时间折算进去：每周花 1 小时修网关的人，时薪 200 元则月成本 800 元，可能超过订阅费。

## 失败复盘：三天弃坑的典型原因

第一天装完觉得酷，第二天接 Slack 失败，第三天觉得「不如网页 Chat」。对照清单：是否跳过记忆初始化？是否在网关未稳定时接了五个平台？是否用复杂任务测而不是探针？把弃坑原因写下来，团队里其他人能少走弯路。

## 局限与不适合谁

Hermes 不是开箱即用的消费者 App，配置 IM Bot、密钥轮换、备份都要人做。对数据出境极敏感且不能用 Honcho 云的组织，要事先做合规评估。若团队编码产出全部在 IDE 内完成、几乎不用 IM 协作，价值会低于专用编码 Agent。功能与渠道以 [官方文档](https://hermes-agent.nousresearch.com/docs) 为准，本文不保证与你本地版本完全一致。
