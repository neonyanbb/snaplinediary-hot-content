## 对比框架：五维而不是「智商榜」

2026 年主流产品都能写像样段落，差异在 **记忆放哪、在哪用、能不能改你的仓库、谁掌控数据、月费结构**。下面表格用于粗选，细项以各产品当期定价页为准。

| 维度 | Hermes Agent | Claude（App/API） | ChatGPT | Cursor |
|------|--------------|-------------------|---------|--------|
| 记忆 | 网关/可选 Honcho，跨 IM | 项目/会话级，依产品 | GPT 记忆功能，依账号 | 仓库索引 + 会话 |
| 主战场 | Telegram/Slack 等 + CLI | 网页/API | 网页/插件生态 | VS Code 系 IDE |
| 改代码库 | 弱于专用编码 Agent | API 可接，非默认 | 有限 | 强，Agent 模式 |
| 开源/自托管 | 开源，可自建网关 | 闭源 | 闭源 | 闭源 |
| 典型月费 | 模型 API + 自运维 | 订阅/API | Plus/Team | Pro ~20 美元档 |

结论先行：**没有「一个换掉全部」**。常见组合是 Cursor 或 Claude Code 写代码，Hermes 管 IM 与长期偏好。选型的核心问题是「你的主要产出发生在哪」，而不是「哪个模型考试分更高」。

## 压力测试：遗留项目重构怎么评

假设任务：2 万行单体，要梳理模块边界并列出迁移步骤（不真改生产）。

**Cursor**：强项是边读边改、可视化 diff，适合你在 IDE 里边看边收。Agent 模式可以跨文件搜索引用、自动生成修改列表。局限是记忆以仓库索引为主，离开 IDE 后无法追问上周的决策。

**Claude Code**：强项是终端里 `/plan`、多文件执行与跑测试，适合委托一整条重构链。它能记住当前仓库的上下文，但跨仓库或跨渠道的记忆需要额外配置。

**Hermes**：若未接代码仓库 MCP，不应期待它自动扫全库；更适合记录「架构决策、风险清单」并在一周后追问进度。它的价值不在写代码，而在保持「你为什么选方案 A 而不是 B」的长期记忆。

**ChatGPT**：上传片段可以，全库一致性弱于 IDE Agent。GPT-4o 的长上下文可以塞进去几万行，但模型容易在中间部分 hallucinate 依赖关系。

**通过标准**：一周后无需重复背景，能答出「上次列的三条风险是什么」。Hermes 与带项目记忆的 Claude 产品更容易过；纯无记忆网页会话容易挂。

## 开源到底带来什么

Hermes 开源意味着：可审计网关逻辑、可内网部署、可 fork 技能。具体好处是：

- 数据不出内网：网关和 SQLite 记忆库完全跑在本地，敏感对话不会经过第三方 SaaS。
- 可定制渠道：官方支持 20+ 平台，你也可以自己写 adapter 接企业内部 IM。
- 模型自由：支持 Claude、OpenAI、本地 Ollama、xAI Grok 等多种 provider，通过配置切换即可。

代价是 **你要负责升级与安全补丁**。闭源产品把运维卖给厂商，适合无专职平台工程师的小团队。开源不等于免费：模型 API、服务器、Honcho 仍可能产生费用。

## 组合建议（可执行）

| 用户类型 | 建议组合 |
|----------|----------|
| 独立开发者 | Cursor 或 Claude Code + Hermes(Telegram) |
| 内容/研究 | Claude 长文 + Hermes 捕获 [KB] |
| 企业研发 | Claude Code + 企业 Wiki，Hermes 需合规评审 |
| 只想聊天 | 单产品即可，不必 Hermes |

独立开发者的典型工作流：白天用 Cursor 写代码，通勤时用 Telegram 语音记录灵感，晚上回家在 CLI 追问「早上那个想法细节」。Hermes 负责把碎片串成线，Cursor 负责把线变成代码。

## 采购会议里可问的五个问题

1. 记忆数据存在哪，能否一键导出与删除？
2. 换模型是否影响历史检索？
3. IM Bot 是否支持最小权限与审计日志？
4. 开源版本与商业支持边界？
5. 发生幻觉时，谁对对外消息负责？

把 ChatGPT、Claude、Cursor、Hermes 放在同一张表里答这五个问题，比争论「谁更聪明」更快收敛。Hermes 在问题 1 和 2 上得分高，Cursor 在代码库能力上得分高，没有全胜者。

## 实测记录模板（建议复制）

```
日期：
任务：遗留模块梳理 / 多文件重构 / 纯写作
tool：
耗时：
返工次数：
一周后是否记得上下文：Y/N
备注：
```

连续记录四周，你会得到 **自己的** 对比数据，而不是营销话术。建议固定任务类型，比如每次都测「2 万行单体模块梳理」，变量只换 tool，这样结果可比。

## 延长对比：编码以外的任务

让各 tool 做 **同一份** 会议纪要整理：输入 2000 字杂乱笔记，要求输出决策、待办、风险。看是否杜撰未出现的「决定」。再让各 tool **一周后** 回答「纪要里的待办谁负责」，测记忆或项目功能。

编码强的不一定纪要准。Claude 擅长长文整理，Hermes 擅长一周后追问，Cursor 不擅长纯文本处理。避免一刀切。

## 给管理者的结论句式

向管理层汇报时，用具体数字代替主观感受：「我们组保留 Cursor 日常 + Claude Code 周度重构 + Hermes 仅 Telegram 捕获，预计月费 X，标准任务节省 Y 小时。」比「必须全员 Hermes」易通过。

计算 Y 小时的方法：选三个重复出现的任务（如代码审查、会议纪要、技术调研），记录人工耗时和 tool 辅助后的耗时，取四周平均值。

## 局限与不适合谁

本文不做性能 benchmark，模型排名随月份变化，任何「最强」结论都会在下次发版后过期。Hermes 不能替代 IDE 内重构 tool；Claude/ChatGPT 也不能默认给你跨 Slack 与 Telegram 的统一网关。

若你所在行业禁止外发代码到第三方，任何云 Agent 都要走企业协议，Hermes 自托管只是降低一部分风险，不消除模型供应商审查。采购前请做法务评估，勿仅凭对比表下单。Cursor 的 Agent 模式需要把代码发送到云端模型，即使是闭源产品，数据流仍然出网。
